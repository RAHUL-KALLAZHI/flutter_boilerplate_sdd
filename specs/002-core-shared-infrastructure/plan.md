## Summary

Implement the foundational reusable shared infrastructure for the LifeHub application inside `lib/core/` and `test/core/`. This establishes the 8 core operational domains: Networking (Dio), Dependency Injection (GetIt/Injectable), Database (Drift), Storage (Secure Storage & Preferences), Routing (GoRouter), Error Handling (Failures & Result), Logging (PII masking), and Testing Scaffolding.

## Technical Context

**Language/Version**: Dart >= 3.4.4 < 4.0.0, Flutter SDK 3.44.5 (FVM)

## Constitution Check (LifeHub Constitution v2.0.0)

*GATE: Must pass before Phase 0 research. Re-check after Phase 1 design.*

- [x] **Principle I: Spec-First & Feature Isolation**: Infrastructure resides in `lib/core/` without coupling to specific feature domain logic.
- [x] **Principle II: State Management with BLoC/Cubit**: Core infrastructure exposes immutable data streams and state listeners (e.g. for authentication state and navigation).
- [x] **Principle III: Dependency Injection & Service Lifecycle**: All services registered via GetIt + Injectable with clear `@singleton`, `@lazySingleton`, and `@module` annotations.
- [x] **Principle IV: Centralized Networking & Error Handling**: Unified Dio client with auth, logging, and error interceptors; errors mapped to domain `Failure` abstractions.
- [x] **Principle V: Local Storage & Abstraction**: Drift SQLite instance with migration manager and clean data source contracts; encrypted storage for credentials.
- [x] **Principle VI: Declarative Navigation**: GoRouter configured with route constants, error boundary, and auth state redirection.
- [x] **Principle VII: Observability & Masking**: Centralized logger with automated regex masking for tokens, passwords, and sensitive keys.
- [x] **Principle VIII: Testing & Quality Gates**: Dedicated unit tests and test helpers (`MockDioAdapter`, in-memory Drift connection, DI test harness).

## Implementation Phases & Strategy

1. **Phase 1: Dependencies & Base Error/Logging Models**
   - Add approved dependencies to `pubspec.yaml`
   - Implement `sensitive_data_masker.dart` and `app_logger.dart`
   - Complete `failures.dart`, `exceptions.dart`, `result.dart`, and `error_handler.dart`
   - Unit tests for errors and logger
2. **Phase 2: Storage & Environment Foundations**
   - Implement `environment.dart`
   - Implement `secure_storage_service.dart` and `preferences_service.dart`
   - Unit tests for storage services
3. **Phase 3: Networking Infrastructure**
   - Implement `api_endpoints.dart`, `auth_interceptor.dart`, `logging_interceptor.dart`, `error_interceptor.dart`
   - Implement `api_client.dart`
   - Unit tests for networking with mocked HTTP adapter
4. **Phase 4: Database Infrastructure (Drift)**
   - Implement Drift platform connection opener (`connection.dart`) and in-memory test opener (`in_memory_connection.dart`)
   - Implement `migration_manager.dart` and `app_database.dart`
   - Run code generation (`drift_dev`)
   - Unit tests verifying database opening and migrations
5. **Phase 5: Navigation Infrastructure (GoRouter)**
   - Implement `route_paths.dart`, `router_listenable.dart`, `not_found_screen.dart`
   - Implement `app_router.dart`
   - Widget/Router tests
6. **Phase 6: Dependency Injection Assembly**
   - Implement `@module` classes for third-party libraries (Dio, Database, Storage)
   - Implement `injection.dart` (`configureDependencies(env)`)
   - Run code generation (`injectable_generator`)
   - Test DI resolution in `test/core/di/injection_test.dart`
7. **Phase 7: Shared Testing Harness & Final Verification**
   - Package `test_injection.dart`, `mock_dio_adapter.dart`, `mock_services.dart`
   - Run full test suite (`flutter test`) and static analysis (`flutter analyze`)
   - Zero warnings, 100% pass rate
